GEN 1 / SHORT

PokeBench Gen 1 Short

Navigation, battles, menus, preparation, and quests.

Harness is the benchmark version each attempt recorded. Rows on different harness versions are not strictly comparable.

Since 14 November 2026 the Short score averages navigation, battles, menus and quests equally, and it no longer counts preparation or the retired Pikachu quest.

Category-balanced score. Click a model to explore its tasks.
How to read this

Scores average starts within task groups, then groups within each category, then the four ranked categories equally: navigation, battles, menus and quests. Preparation is scored and shown, but it is not ranked. It uses a fixed battle controller to assess the model's choices. Other tasks score completion. Retired tasks keep their old attempts on the page, but they are not scored. Pending trials and evaluation errors are excluded, not counted as failures.

The range under each score is a 95% bootstrap interval. It resamples tasks within each category 2,000 times and keeps the category weights. It shows how much the score depends on which tasks were chosen. It does not capture run-to-run luck, because each start was played once. Ranks are by point score.

Astra and Fable use the current interface and revised Mt. Moon, Pikachu capture, Bicycle, and scarce-resource League tasks. Earlier results are preserved. Models with unfinished trials are marked provisional. This is an exploratory comparison, with one attempt per registered start.

RUN IT YOURSELF

Submit a model

Run PokeBench Short on your own machine and send the result. A maintainer replays every run and then decides whether to publish it.

You need uv, git, the model you want to test and your own Pokémon Red ROM. PokeBench ships no ROM, and setup accepts only the one file the README names by its hash.

Full guide in SUBMITTING.md ↗

The three commands

Run them in an empty folder. No clone is needed.

uvx --from git+https://github.com/afk-sapien/pokebench@v0.37.4 pokebench setup --rom /path/to/red.gbuvx --from git+https://github.com/afk-sapien/pokebench@v0.37.4 pokebench enter --suite smoke --provider randomuvx --from git+https://github.com/afk-sapien/pokebench@v0.37.4 pokebench enter --suite short --model MODEL --handle YOUR_GITHUB_NAME
  1. Setup checks the ROM hash and writes the data folder.
  2. Smoke is a free check of the whole path. A random player plays three tasks and no model is called. Do not send this bundle.
  3. Short runs your model. It prints the plan and asks before the first model call. When every task has finished it packs the bundle and prints a link to a prefilled submission issue.

A model id starting with claude uses your Claude Code login and one starting with gpt uses your Codex login. For a local model, point PokeBench at any OpenAI compatible endpoint that accepts images and reports token usage:

export POKEBENCH_BASE_URL=http://localhost:11434/v1uvx --from git+https://github.com/afk-sapien/pokebench@v0.37.4 pokebench enter --suite short --provider openai-compatible --model MODEL --handle YOUR_GITHUB_NAME

What it costs

Local model: free. It uses only your own computer.

Hosted model: see SUBMITTING.md for the token caps.

What we check

  • The run comes from release v0.37.4, installed unchanged.
  • It covers the whole Short suite with the same starts, task definitions and limits.
  • Every run is replayed from our own start state. The recorded inputs must reproduce the recorded game, and the score is recomputed from the replay.
  • No run passes its decision or token limit.

What we cannot check

  • What chose the inputs. A person, a script or another model could have produced them.
  • The model name, the token counts, the number of attempts and the absence of outside help. These are self reported.
  • Whether the best of many runs was sent. Please declare your attempts.

So a published community row carries the label “Community, replay verified, model unverified”, with your GitHub name if you gave one and your declared attempts.

THE BENCHMARK

A familiar game.
An unfamiliar player.

Models control Pokémon Red through an emulator. Short tasks isolate specific skills. Long runs test whether those skills hold together across an adventure.

Strategy tasks provide game information and mechanical shortcuts. Menu-operation tasks require the model to operate the controls. Every attempt has a decision and token budget.
