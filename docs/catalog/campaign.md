# Full-game campaign: 50 milestones and a run profile

This is a scoring plan for one continuous attempt, not 50 separate trials. The existing runtime scoring is unchanged. New event collectors and score integration remain pending.

Champion completion is the primary outcome. The proposed progress score has a 1000-point maximum, with the following breakdown. Optional collection bonuses are not required to pass the game.

| Component | Milestones | Points |
| --- | ---: | ---: |
| Story and quest progress | 20 | 100 |
| Town and League access | 10 | 50 |
| Gym badges | 8 | 400 |
| Elite Four | 4 | 200 |
| Champion and Hall of Fame | 1 | 200 |
| Capture and team development | 7 | 50 |

- **Assemble a party of six distinct species**: 10 points. Confirm six different species simultaneously in the party through legal acquisitions. This measures roster breadth, not tactical quality. Reordering and repeated assembly do not score again.

## Scoring rules

- Champion completion is the primary outcome. Show the 0 to 1000 progress score and its category breakdown alongside it, rather than replacing completion with collection totals.
- Each milestone earns its listed points at most once per attempt. Counts are cumulative thresholds, so 20 distinct wild species earns 25 capture points in total, not 20 points per catch.
- Exclude facts already true at the supplied start. The official campaign starts fresh. No resets, repeated purchases, repeated map visits or repeated easy battles generate extra points.
- Milestone points never decrease. Keep blackouts, item waste and current party condition in the run profile so they explain progress without erasing completed achievements.
- The optional collection component is capped at 50 points. Becoming Champion does not require collecting every bonus, and 1000 points is not required for a full-game pass.
- Award progress from verified game evidence. Do not infer completion from the agent notebook or a claimed tool result. Missing telemetry is unknown, not a zero or an automatic failure.
- Record the first achievement time, frame, decision and cumulative token use. These are 50 observations within one trajectory, not 50 independent trials.
- Publish the score definition to agents before an evaluated run. Keep hidden evaluator state private, and give every model the same scoring rules and budget.
- The weights are provisional design choices. Pilot the breakdown before using it for model ranking. Do not relabel historical scores without enough saved evidence to recompute this definition.

## Holistic run profile

### Party strength and readiness

At the start, each badge, League entry and attempt end, save the roster, levels, total and median level, HP/max HP, nonfainted count, status, remaining move PP, Attack, Defense, Speed and Special. Show stat totals as descriptive proxies, not a calibrated battle-power score.

Party levels, HP, status and PP are available in current observations. Full stat snapshots and standardized reporting need integration.

### Moves and team coverage

Show damaging move types with usable PP, status/setup/recovery moves and field moves. Coverage describes available options. It is not a claim that all matchups are winnable.

Move IDs and PP are available. Coverage aggregation needs integration.

### Collection and development

Track successful capture events, distinct wild species caught, distinct owned species, evolutions and species held in the party or PC separately. Dex-owned counts include gifts and evolutions, so they are not a substitute for capture counts.

Dex ownership and current party are readable. Capture/evolution provenance and storage history need integration.

### Battle outcomes and setbacks

Track trainer wins by unique trainer, wild wins, escapes, faints and blackouts separately. Show losses and recoveries at matched progress milestones. Farming wild wins earns no extra score.

Battle state is available. Persistent verified outcome counters need integration.

### Purchases, item use and money

Record bought and sold quantities by item, purchase spending, sale proceeds, reward income, blackout losses, item use and remaining supplies separately. Report purchases without awarding points for spending.

Current money and bag are readable. Transaction provenance needs integration. Inventory and money deltas alone must not be called purchases.

### Efficiency at comparable progress

Show cumulative reported tokens with input/output/cache breakdown, decisions, actions, game frames and elapsed time at each milestone. Compare efficiency at the same achieved milestone. Do not count cached input twice or label subscription usage as actual API charges.

Run token and action logs exist. Milestone joins and dashboard presentation need integration.

## Implementation boundary

- Validate the fresh-game checkpoint and bind each of the 50 milestone predicates to native game evidence.
- Integrate a persistent event history for captures, evolution, location visits, purchases and battle outcomes. Retain this history across context resets and process resume.
- Apply the proposed scoring definition only to new evaluated runs or historical traces with sufficient evidence. Existing runtime scoring remains unchanged by this plan.
- Record the party and resources at matched milestones, and join milestone events to cumulative tokens, decisions, frames and time.
- Pilot milestone weights and collection thresholds before using the new score in the leaderboard. No model sweep is launched by editing this plan.
