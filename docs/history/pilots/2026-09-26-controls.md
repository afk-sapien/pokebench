# Subscription control pilot

Four live runs used ChatGPT-authenticated Codex CLI 0.147.0. The account model
list exposed `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, and `gpt-5.5`.
Sol and Luna were selected before running either model. No paid API provider,
reset credit, retries, or additional model runs were used.

Both models used low reasoning effort and the structured observation track.
Each task had a 30,000 reported-token threshold, three model calls, three
actions, 360 emulator frames, a 120-frame action ceiling, and 120 wall seconds.
Threshold enforcement occurs between decisions. A crossing response is counted
but its controller action is not executed.

| Adjacent tile | gpt-5.6-sol | Completed | 2 | 2 | 23,756 | 11.88 |
| Adjacent tile | gpt-5.6-luna | Token threshold | 3 | 2 | 30,988 | 14.48 |
| Close menu, then adjacent tile | gpt-5.6-sol | Token threshold | 3 | 2 | 35,541 | 15.92 |
| Close menu, then adjacent tile | gpt-5.6-luna | Token threshold | 3 | 2 | 31,498 | 17.39 |

Total reported input plus output was 121,783 tokens over 11 calls. Usage
accounting was complete for every run. The account meter moved from 17% to 18%
weekly usage during this work. That rounded, shared meter cannot isolate the
pilot's subscription cost from other account activity.

All four action traces passed deterministic replay with matching frame counts,
screenshots, evaluator evidence, and trace hashes. The controller references
completed the tile and menu tasks in one and two actions respectively. Exact
run artifacts remain under `runs/subscription-pilot-*`. The source checksum,
scenario hash, prompt hash, CLI version, limits, and reasoning effort are in
each run manifest. The frozen aggregate export is
`paper/analysis/inputs/benchmark.json`.

The tile trials share comparison group `2a63219d86bb`. The menu trials share
`660f936fc8fb`. The verified menu scenario is under
`scenarios/verified-control-pilot/mansion-close-menu-v1`. Preparation is
reproducible with `scripts/prepare_control_pilot.py` and the private source
checkpoint. Initial screen checksums are bound to the prepared scenarios.

## Findings and limits

The live subscription adapter returned valid actions and token usage for both
models. One-frame movement presses did not move the character in these trials.
Sol used a longer press to finish the tile task. It also requested a longer
movement press on the menu task, but that response crossed the token threshold
and was not applied.

Fresh Codex decisions carried roughly ten to twelve thousand input tokens each,
including harness context. A 30,000-token threshold therefore allowed only two
executed actions in these runs. This is a harness and budget calibration pilot,
with one observation per model and task. It does not establish a model ranking,
battle competence, or full-game progress.

Next work should reduce repeated harness context, make controller timing clear,
and validate a budget that permits meaningful short tasks. Preserve these pilot
results. Any changed prompt, action semantics, or budgeting protocol belongs in
a new benchmark version and comparison group.
